# Security Policy

## Supported versions

This project is still in an early release cycle. Security fixes are handled on the current main branch and the most recent tagged release.

## Reporting a vulnerability

Please do not open a public GitHub issue for a security vulnerability.

Use a private disclosure path and include:

- affected version or commit
- reproduction steps
- expected result
- actual result
- risk assessment

## Do not publish

Do not include

- secrets
- API keys
- database credentials
- JWTs
- customer or prospect data
- tokens
- private URLs

in issues, PRs, or logs.

## Responsible disclosure

We ask that vulnerabilities be reported privately and responsibly before public disclosure. The goal is to fix the issue and communicate a safe remediation path without exposing customer data or deployed systems.
