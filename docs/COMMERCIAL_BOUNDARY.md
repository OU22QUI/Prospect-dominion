# Commercial Boundary

## Open Source Core

The public core remains free and open for:

- workflow foundation
- deployment scripts
- validation logic
- Postgres-backed pilot path
- demo experience
- local runtime and docs
- operator education and self-hosted experimentation

The shared core is MIT-licensed. Aethonex does not claim exclusive ownership of the core or restrict use of the public software. Customers retain their data, credentials, and infrastructure; rights to bespoke work and any paid deliverables must be defined in the signed scope.

The free Core is the distribution wedge. It is not the full customer delivery model.

## Aethonex Services

Customers pay Aethonex for:

- deployment into a real customer environment
- DNS/TLS configuration
- secret management and environment hardening
- workflow implementation around the customer process
- operational support and updates
- data source integration and custom tuning
- pilot delivery and handover
- customer-specific governance and approval setup

This is where the real commercial value sits: taking the core and making it work in a real business workflow.

## Strategic Priorities

The operating model is intentionally simple:

1. Freeze and finalize the core.
2. Open-source the useful core.
3. Sell implementation, not software access.
4. Keep Aethonex Services outbound running.
5. Use the OSS repo as a distribution engine.
6. Productize repeated implementation work into paid modules.

This strategy keeps the public project credible, useful, and commercially viable without over-claiming what the free core alone is designed to do.

## Future Commercial Modules

Potential premium modules may include:

- advanced connectors
- specialized workflow packs
- additional governance or approval patterns
- monitoring and support tiers
- operational runbooks tailored to customer environments

These are future opportunities, not hidden paid features inside the core.
